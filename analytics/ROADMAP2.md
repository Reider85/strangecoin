Анализ ROADMAP.md: согласия, несогласия и дополнения
| Пункт                                       | Комментарий                                                                                                                                                   |
| ------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Приоритет Этапа 0**                       | Абсолютно верно — без подписей транзакций, валидации difficulty и детерминированного генезиса всё остальное бессмысленно. Это не roadmap, а **precondition**. |
| **Критические проблемы 1–13**               | Все 13 пунктов точно диагностированы. Особенно силён анализ «balances problem» как тавтологии.                                                                |
| **Mainnet freeze**                          | Ключевой инсайт: параметры эмиссии, генезис и ретаргетинг **должны быть неизменны** после запуска. Это разделяет «игрушку» и «деньги».                        |
| **Каноническая сериализация**               | JSON для хэшей — это классическая ошибка новичков. Согласен на 100%.                                                                                          |
| **OOM-вектор**                              | `vec![0; length]` — критическая DoS-уязвимость, которую часто упускают.                                                                                       |
| **WASM/RISC-V вместо рукописного байткода** | Это профессиональный уровень мышления. Собственный байткод = годы аудита.                                                                                     |
| **Multidimensional fees (EIP-4844/7706)**   | Продвинутая идея, показывает глубокое понимание современных проблем Ethereum.                                                                                 |
| **Verkle Trie + stateless validation**      | Амбициозно, но правильно — это направление, в котором движутся Ethereum и Polkadot.                                                                           |
| **Shadow-fork testing**                     | Заимствовано из практики Ethereum — отличный пример learning from the best.                                                                                   |
| Пункт                                                   | Моё мнение                                                                                                                                                                                                                           |
| ------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Finality gadget (Casper FFG / Grandpa / Tendermint)** | Для одного разработчика это **over-engineering**. PoW с 10-минутными блоками и 6 подтверждениями — достаточно для MVP. Finality gadget добавляет сложность, которую сложно правильно реализовать и аудировать. **Отложить до 2.x+**. |
| **Parallel execution (Block-STM)**                      | Block-STM — это cutting-edge research (Aptos, 2022+). Для проекта на стадии 0.8.x это **неприоритетно**. Сначала нужна **корректная** последовательная валидация, потом — параллельная.                                              |
| **Account Abstraction (ERC-4337)**                      | Слишком сложно для ранней стадии. Добавляет attack surface (paymaster, bundler). **Отложить**.                                                                                                                                       |
| **State rent / expiry**                                 | Важно, но спорно. Ethereum отказался от state rent в пользу statelessness + pruning. Может быть, лучше скопировать их подход?                                                                                                        |
| **MEV mitigation (PBS / threshold encryption)**         | PBS — это **production-grade** инфраструктура (Flashbots, ~2023). Для новой цепочки MEV изначально минимален. **Не приоритет**.                                                                                                      |
| **EIP-1559 + multidimensional fees**                    | EIP-1559 — отличная идея, но multidimensional fees (EIP-7706) ещё не принят в Ethereum. Для новой цепи лучше начать с **простого фиксированного gas limit**, а потом эволюционировать.                                               |
| Пункт                                  | Проблема                                                                                                                                                                                                                     | Альтернатива                                                                                                                                       |
| -------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| **PoW как долгосрочный консенсус**     | PoW в 2026+ — это **устаревшая модель**. Энергозатраты, централизация майнинга (ASIC), низкая финальность. Для новой цепи лучше сразу выбрать **PoS или PoW?PoS миграцию**.                                                  | Или: **PoW только для genesis/fair launch**, затем переход на PoS (как Ethereum).                                                                  |
| **21M cap + halving**                  | Копирование Bitcoin без обоснования. Фиксированный supply cap создаёт **дефляционный спиральный риск** (hodling ? низкая ликвидность).                                                                                       | Рассмотреть **tail emission** (как Monero: 0.6%/год) для постоянной безопасности сети. Или **динамическую эмиссию**, привязанную к TVL/активности. |
| **Ed25519 для подписей транзакций**    | Ed25519 — хорош, но в блокчейнах **стандарт de facto — ECDSA secp256k1** (Bitcoin, Ethereum) или **BLS** (Ethereum 2.0, для агрегации подписей). Ed25519 усложняет интеграцию с существующими кошельками (MetaMask, Ledger). | Для совместимости: **secp256k1** (ECDSA) или **BLS12-381** (если планируется PoS/сигнатурная агрегация).                                           |
| **LevelDB ? redb/rocksdb**             | redb — хорош, но **RocksDB** (или даже LMDB) — battle-tested в production (Bitcoin Core, Ethereum). Для одного разработчика лучше взять **проверенное решение**, чем экспериментировать.                                     | RocksDB + паттерн «column families» (как в reth).                                                                                                  |
| **WIT / Wasm Component Model для ABI** | Wasm Component Model — слишком новый стандарт (W3C, 2023+). Мало tooling, мало аудитов.                                                                                                                                      | Для MVP: **простой JSON ABI** (как в Ethereum), потом — переход на стандартизированный формат.                                                     |
| **Отсутствие лицензии**                | Это **критическая ошибка**. Без лицензии код нельзя легально использовать/форкать.                                                                                                                                           | Добавить **MIT/Apache-2.0** (как в Rust-экосистеме) или **GPL-3.0** (если хотите copyleft).                                                        |
| Пункт                             | Почему важно                                                                                                      |
| --------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| **Replay protection (chain\_id)** | Без `chain_id` транзакции из testnet будут валидны в mainnet и наоборот. Классическая атака.                      |
| **Nonce / sequence number**       | Сейчас нет защиты от replay внутри одной цепи. Один и тот же `sender` может отправить одну транзакцию бесконечно. |
| **Transaction hash = commitment** | Нужен уникальный идентификатор транзакции для отслеживания, мемпула, отката.                                      |
| **Mempool с basic rules**         | Даже простой: проверка баланса, nonce, подписи, дедупликация. Без мемпула — нет «pending» транзакций.             |
| **Graceful shutdown**             | Сейчас «ручное удаление LOCK» (`main.rs:188`). Нужен корректный `Drop` для LevelDB + flush буферов.               |
| Пункт                              | Почему важно                                                                                                                 |
| ---------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| **Event log / receipts**           | Без логов невозможно строить эксплорер, индексатор, dApps. Ethereum без `logs` — не Ethereum.                                |
| **Block gas limit**                | Даже фиксированный лимит (например, 1M gas) защищает от блоков, которые валидируются вечно.                                  |
| **P2P message framing с max size** | Не просто «лимит размера», а **proper framing**: length-prefixed, с проверкой до аллокации.                                  |
| **Rate limiting на P2P**           | Защита от spam: лимит сообщений/сек от одного пира.                                                                          |
| **Configuration management**       | Сейчас `config.json` + `config.toml` + секция `[wallet]` в `Cargo.toml` — бардак. Нужен единый `Config` struct с валидацией. |
