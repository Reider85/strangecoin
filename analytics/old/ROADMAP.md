# ROADMAP: путь Strangecoin к зрелой криптовалюте

Анализ выполнен по состоянию репозитория на версию 0.8.6. Код компилируется
(`cargo check` без ошибок, ~20 предупреждений), это рабочий прототип.

## Текущее состояние

- **Консенсус**: PoW, `difficulty=2`, но майнинг искусственно ограничен
  (1000 итераций / 5 сек таймаут, `src/main.rs:479`). Монолит: блокчейн + сеть +
  GUI в одном `src/main.rs` (1756 строк) + `src/wallet.rs`.
- **Криптография**: кошелёк на Ed25519 с шифрованием ключа (PBKDF2 + AES-256-GCM),
  сделано прилично (`src/wallet.rs`). Но транзакции **не подписываются**:
  `sign_transaction` (`wallet.rs:191`) нигде не вызывается.
- **Персистентность**: LevelDB (chain, balances, difficulty, транзакции по UUID).
- **Сеть**: сырой TCP, два сообщения `GET_BLOCKCHAIN`/`UPDATE_BLOCKCHAIN`,
  пиры из статического `network.json`.

## Критические проблемы (блокируют «зрелость»)

1. **Нет подписей транзакций** — любой может потратить чужие монеты
   (`main.rs:1508` создаёт `Transaction` без подписи; поле отправителя — просто строка).
2. **`validate_chain` не проверяет сложность PoW** (`main.rs:646–740`) — проверяет
   хэш блока, но не то, что он начинается с N нулей.
3. **Валидация балансов тавтологична**: `expected_balances` берётся из
   `self.balances` (`main.rs:668`), а не выводится из генезиса+цепочки → манипуляции
   с балансами не обнаруживаются. Это и есть «balances problem» из Changelog.
4. **Нет награды за блок/эмиссии** — майнить невыгодно, нет расписания эмиссии,
   нет supply cap.
5. **Генезис недетерминирован** (случайный UUID, фиксированный адрес
   `initial_wallet_address`, `main.rs:305`); баланс в 10000 никому реально не принадлежит.
6. **Адреса = base64 без контрольной суммы** — опечатка = потеря средств.
7. **`find_wallet_by_ip` возвращает первый попавшийся баланс** (`main.rs:933`),
   а не кошелёк по IP.
8. **Регистрация мутирует `balances` напрямую** (`main.rs:1423`) — не через
   блокчейн, узлы рассинхронизируются.
9. **Пароль в открытом виде** в `config.json:4`.
10. **Синхронизация ad-hoc** — гонки, эвристика «длина блока», без gossip; единый
    глобальный `Mutex<Blockchain>`, майнинг блокирует весь узел.
11. **Нет тестов** (тест `test_two_clients` упомянут в Readme, но отсутствует),
    нет CI.
12. **DoS: неограниченный размер сообщений** — сервер читает `length: u32` и
    аллоцирует `vec![0; length]` (`src/main.rs:961`): пир может прислать
    `0xFFFFFFFF` и уронить ноду по памяти.
13. **Неканоническая сериализация и нет проверки времени блоков** — подпись/хэш
    строятся на JSON, timestamp из будущего не отклоняется (нет median-time-past).

## Этап 0 — Санация прототипа (0.9 → 1.0, приоритет: критический)

Минимум для того, чтобы монетой нельзя было украсть/сломать:

- [ ] Подпись и проверка каждой транзакции Ed25519 (задействовать готовые примитивы
      `wallet.rs`), верификация при приёме и синхронизации; `sender` обязан
      совпадать с публичным ключом подписанта
- [ ] Каноническая (бинарная, детерминированная) сериализация транзакций/блоков:
      подпись и хэш строятся на ней, не на `serde_json::to_string`
- [ ] Проверка difficulty в `validate_chain` + запрет снижения difficulty иначе как
      по правилу; алгоритм ретаргетинга (эпоха/скользящее окно по реальному
      времени блоков) фиксируется до запуска сети
- [ ] Валидация времени блока: median-time-past, запрет timestamp из будущего
- [ ] Детерминированная валидация: балансы выводятся из генезиса, `self.balances`
      только кэш; несоответствие = откат
- [ ] Детерминированный генезис, привязка начальной эмиссии к реальному ключу;
      параметры эмиссии (max supply, награда, halving) фиксируются в генезисе
      до запуска основной сети (mainnet freeze)
- [ ] Награда за блок + базовая эмиссия (делает майнинг осмысленным); убрать
      искусственные лимиты майнинга (1000 итераций / 5 сек), оставить честный PoW
- [ ] Лимиты размера: сообщение, блок, транзакция (закрыть OOM-вектор
      `vec![0; length]` в `src/main.rs:961`)
- [ ] Разбить на модули: `blockchain/`, `consensus/`, `network/`, `mempool/`,
      `storage/`, `api/`, `cli/`, `gui/`
- [ ] Юнит- и интеграционные тесты, устранение 20 warning'ов и мёртвого кода
      (`mining_thread`, `config.toml`, секция `[wallet]` в Cargo.toml)

## Этап 1 — Криптографическое ядро (1.x)

- [ ] Адреса с контрольной суммой (bech32-подобные), валидация адреса клиентом
- [ ] Меркл-корень транзакций **и состояния** в блоке → SPV-совместимость,
      невозможно скрытое искажение балансов
- [ ] Синхронизация заголовков (headers-first) вместо пересылки всей цепочки
- [ ] Комиссии, приоритизация мемпула, защита от double-spend в мемпуле
- [ ] Поток майнинга без блокировки сети (`RwLock`, worker-пул)
- [ ] **Finality gadget** (Casper FFG / Grandpa / Tendermint) — PoW + finality = быстрее подтверждения
- [ ] **Checkpoint sync** (weak subjectivity) — быстрая синхронизация новых узлов
- [ ] **Reorg protection**: rolling checkpoints по height, не по времени

## Этап 1.5 — Смарт-контракты (1.5.x, собственный механизм Strangecoin)

Строится на детерминированной валидации и state root из Этапа 1; до них
закладывать контракты бессмысленно.

- [ ] **Выбор рантайма VM**: WASM (wasmi/wasmer) ИЛИ RISC-V (ckb-vm/risc0) —
      формальная семантика, готовые фаззеры, LLVM-бэкенд для контрактов на Rust.
      Отказ от рукописного байткода = годы экономии на аудите.
- [ ] Аккаунт-модель: EOA + контрактные (code, storage trie, nonce, balance)
- [ ] Host functions: `ed25519_verify`, `blake3`/`keccak`, `blockhash`,
      `storage_read`/`write`, `call`/`delegatecall`/`staticcall`, `gas_left`
- [ ] Gas metering: instruction counting + host-call weights (не таблица опкодов вручную)
- [ ] Типы транзакций: `transfer` / `create` / `call`; payload вызова входит в
      подписываемые данные
- [ ] Газ: лимит на блок, рефанды за освобождение хранилища, динамическая базовая
      комиссия (EIP-1559) + **multidimensional fees** (calldata / blob / storage writes — по EIP-4844/7706)
- [ ] Состояние контрактов в общем state trie → корень состояния в каждом блоке
- [ ] **Sparse Merkle Trie** (Ethereum-style) или **Verkle Trie** для stateless validation witnesses
- [ ] **Parallel execution (Block-STM / optimistic concurrency)** — из коробки
- [ ] Reentrancy guard, лимиты на размер кода/хранилища/стек/память
- [ ] ABI: **WIT / Wasm Component Model** (канонический encode/decode) + события/logs
- [ ] Формальная спецификация VM (K-framework / TLA+) + fuzzing (`cargo-fuzz`/proptest) +
      дифференциальное тестирование с эталонным интерпретатором
- [ ] Стандарты токенов (SCIP-20 / SCIP-721); изменение VM — только через SCIP +
      activation height
- [ ] **State rent / expiry** (EIP-4444 + state expiry) — ограничение роста исторического state
- [ ] **Fee abstraction / Account Abstraction** (ERC-4337 analog): paymaster, bundler, userOps в мемпуле
- [ ] **Upgradeability pattern**: proxy + implementation через governance (SCIP), не через admin key

## Этап 2 — Сетевая зрелость (2.x)

- [ ] Gossip-протокол для транзакций и блоков (announce + инвентарь, как Bitcoin `inv`)
- [ ] **Compact blocks (BIP 152) + Erlay** — эффективный relay на 10k+ узлов
- [ ] Реальный discovery пиров: seed-узлы, addr-госсип, бутстрап
- [ ] P2P-handshake: версии, capabilities, auth узлов
- [ ] Peer scoring, баны, защита от eclipse-атак
- [ ] **P2P transport encryption (Noise / TLS 1.3)** — защита от сниффинга и MITM
- [ ] Режимы testnet/regtest, сценарии сетевых тестов (партиции, расхождения цепей)
- [ ] **Shadow network** для реплея mainnet-блоков перед апгрейдами

## Этап 3 — Хранилище и производительность (3.x)

- [ ] **Миграция на redb / rocksdb с snapshots** — persistent trie для state root (как reth/mdbx)
- [ ] Правильная схема ключей: индекс адрес→UTXO/баланс, чекпоинты состояния
- [ ] Прунинг старых блоков, компактизация, crash-recovery без «ручного удаления
      LOCK» (`main.rs:188`)
- [ ] Пакетная валидация, кэши состояния
- [ ] **Stateless validation witnesses** (verkle proofs) — light-клиенты верифицируют блоки без полного state
- [ ] **State pruning / expiry** (EIP-4444) — удаление исторического state старше N блоков

## Этап 4 — Публичный интерфейс (4.x)

- [ ] **Fuzzing harness**: `cargo-fuzz` целевые контракты + VM из коробки
- [ ] **Indexer (Subgraph / sqd-аналог)** — GraphQL API для дApps
- [ ] **Language servers / IDE support**: Rust analyzer для контрактов, форматтеры

## Этап 5 — Экономика (5.x)

- [ ] Комиссионный рынок, min relay fee
- [ ] **Emission curve: фиксируется до mainnet freeze** (например: 21M cap, halving каждые 4 года, tail emission 0.5%/год для безопасности PoW)
- [ ] **MEV mitigation**: PBS (proposer-builder separation) ИЛИ threshold encryption мемпула

## Что делать в первую очередь

Минимальный шаг к «неуязвимому» состоянию — пункты Этапа 0: подписи транзакций,
проверка difficulty, детерминированная валидация балансов и награда за блок.
Без них остальное бессмысленно, т.к. монета сейчас фактически крадётся простым
редактированием поля `sender`.

Дополнительно до первого публичного запуска сети: закрыть OOM-вектор по размеру
сообщений, зафиксировать генезис, параметры эмиссии и алгоритм ретаргетинга
(mainnet freeze). После запуска любые изменения — только через активацию по
высоте блока.
