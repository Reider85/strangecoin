# Launch-day runbook — `v3.0.0-stage3` (GITHUB.md P5, item 5)

> Синхронизация stage-релиза с анонсом на 4 площадках в один день,
> чтобы всплеск звёзд в окне 24–72 ч дал z-score для Rust Trending.
> Черновики постов: `launch-stage3.md`. Готовность: `trending-checklist.md`.
>
> **Precondition:** Stage 3 закрыт (S3-P09..S3-P15, тег `v3.0.0-stage3`).
> На дату составления (2026-11-09) Stage 3 не завершён — **дата T-дня
> назначается только после DoD Stage 3** (промпт S3-P15).

## Таймлайн

### T−7d — контент в индексацию

- [ ] Опубликовать **dev.to статью** из `launch-stage3.md` §3
      (`published: true`, дата T−7d; длинный контент должен успеть
      проиндексироваться до всплеска).
- [ ] Обновить чек-лист: ссылка на опубликованную статью.
- [ ] Пройти `trending-checklist.md` целиком — закрыть все ❌
      (social preview, Discussions, P1 pre-release).
- [ ] Убедиться, что `star-monitor.yml` уже собирает CSV
      (≥ 168 строк к T−7d дают полноценный `delta_7d`).

### T−1d — релиз

- [ ] Проверить: CI зелёный на `master`, последний pre-release ≤ 24 ч.
- [ ] Создать **настоящий** тег `v3.0.0-stage3` (annotated) и запушить:
      запустится полный `release.yml` (6 платформ + SHA256 + SLSA +
      cosign). **Не** содержит `-dev.` — dev-теги release.yml игнорирует.
- [ ] Проверить, что GitHub Release создан, все 6 артефактов и подписи
      на месте.
- [ ] Отложить посты (черновики готовы): HN, r/rust, r/CryptoCurrency,
      lobste.rs, X/Twitter.

### T=0 — Show HN (09:00 PT = 17:00 UTC = 20:00 МСК)

- [ ] Опубликовать **Show HN** (заголовок + body из `launch-stage3.md` §1,
      дословно). Лучшее окно: вторник–четверг.
- [ ] Не обновлять/не редактировать пост в первые 30 минут (алгоритм HN
      не любит редактирование сразу после сабмита).

### T+15m — вторая волна

- [ ] **r/rust** (пост из `launch-stage3.md` §2).
- [ ] **r/CryptoCurrency** — тот же текст, адаптировать заголовок под
      правила саба (самопромо раз в N дней — проверить правила).
- [ ] **lobste.rs** — короче, акцент «from-scratch Rust L1 + MCP».

### T+1h — соцсети

- [ ] X/Twitter: GIF из README (`assets/strangecoin-demo.gif`) + ссылка
      на репо + ссылка на статью dev.to.
- [ ] Отвечать на комментарии HN в первые 2–3 часа — это прямой фактор
      удержания поста на первой странице.

### T+24h — замер всплеска

- [ ] Открыть `analytics/stargazer-history.csv` (или Actions → Star
      monitor): последняя строка, `delta_24h`.
- [ ] **≥ 20 звёзд за 24 ч** → высокий шанс на Rust Trending Today
      (порог входа 15–40 для Rust; при 1 старте до запуска даже +20 —
      это z-score ≫ 2 от собственной истории).
- [ ] Discord-alert при `delta_24h ≥ 10` должен был прийти сам
      (`star-alert.yml`, если задан `DISCORD_WEBHOOK_URL`).

### T+72h — тренды

- [ ] Проверить `https://github.com/trending/rust?since=daily`
      (T+24h) и `?since=weekly` (T+72h).
- [ ] Зафиксировать итог в CSV + краткую ретро-ссылку в
      `analytics/` (что сработало: какая площадка дала больше всего
      звёзд — `delta_24h` по часам вокруг каждого поста).

## Регламент дня

- **Один координатор** публикует все посты (один и тот же аккаунт/тайминг).
- **Никаких новых тегов и релизов в T−1d…T+1d**, кроме запланированного
  `v3.0.0-stage3` — лишний шум в Releases мешает основному сообщению.
- Промпт-статус: **не выполнять P5 повторно** — файлы уже существуют;
  в день запуска только отмечать чек-лист.

## Что мониторить (автоматика P5)

| Сигнал | Источн | Действие |
| --- | --- | --- |
| Ежечасный снапшот звёзд | `star-monitor.yml` → `analytics/stargazer-history.csv` | смотреть `delta_24h`/`delta_7d` |
| Alert при +10 звёздах/24ч | `star-alert.yml` → Discord | проверить Trending по ссылке из сообщения |
| История для z-score | `analytics/stargazer-history.json` (пишет `prerelease.yml`) | сравнивать count перед/после каждого поста |
