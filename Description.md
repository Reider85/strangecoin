Объяснение изменений

Проверка адреса отправителя:

Добавлена проверка if tx.sender != "genesis", чтобы пропускать вычитание суммы из баланса для адреса "genesis". Это отражает специальную роль "genesis" как источника начальной эмиссии, который не требует наличия средств.


Обновление баланса только для получателя:

Для получателя (tx.receiver) баланс увеличивается на tx.amount (в данном случае 10000 добавляется к "initial_wallet_address").
Для обычных отправителей (не "genesis") добавлена проверка достаточности средств перед вычитанием, чтобы сохранить логику валидации для будущих транзакций.


Сохранение логики блокчейна:

Остальная часть метода осталась без изменений: создание транзакции, формирование блока, вычисление хэша и добавление блока в цепочку. Это гарантирует, что генезис-блок корректно формируется и сохраняется.



Дополнительные замечания

Адрес "initial_wallet_address": В текущем коде используется заглушка "initial_wallet_address". В реальной системе этот адрес должен быть заменён на действительный адрес кошелька (например, публичный ключ первого узла или администратора). Можно сделать его настраиваемым через параметр метода или конфигурацию, но без прямого чтения балансов из config.json.
Сохранение в LevelDB: После создания генезис-блока метод Blockchain::new вызывает self.save_state(), который сохраняет self.balances в LevelDB. Это гарантирует, что баланс "initial_wallet_address" (10000) будет сохранён и загружен при следующем запуске приложения.
Альтернативный подход: Если в системе предполагается, что "genesis" должен иметь начальный баланс, можно инициализировать его в self.balances перед созданием транзакции, например:
rustself.balances.insert("genesis".to_string(), u64::MAX);
Однако это менее предпочтительно, так как может усложнить логику и требует дополнительных проверок.

Вывод
Ошибка attempt to subtract with overflow возникала из-за попытки вычесть 10000 из нулевого баланса адреса "genesis". Исправленный метод create_genesis_block решает эту проблему, исключая вычитание для специального адреса "genesis", что соответствует логике начальной эмиссии в блокчейне. При этом баланс получателя корректно обновляется, и данные сохраняются в LevelDB, обеспечивая согласованность с требованиями системы.
